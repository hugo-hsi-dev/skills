# Audit and scope reference

Load for `OPERATION=audit`, a scope decision, or a redesign implementation before direction. Use the routing values already set in the main recipe; do not redefine them here. An audit reports observable evidence and never edits or silently becomes implementation.

## Audit defaults

For each distinctive or restrained choice, identify evidence from the brief, audience, content, task, or identity. Flag defaults without a job: centered headline/glow/three equal cards; identical cards or image-text zigzags; ornamental metadata; category-default purple-blue technology glow or beige-brass luxury palettes; oversized type, glass, grain, or animation substituting for hierarchy; generic or fabricated claims; and fake screenshot fragments. State the consequence and smallest correction. Familiarity is valid for operational and public-service interfaces when it improves speed or trust.

Match the correction to the surface:

- Marketing/launch: ownable composition, concise value proposition, real proof, controlled conversion.
- Portfolio/creative: expressive type and variance while samples, authorship, and navigation stay clear.
- Editorial: readable measure, pacing, image-caption relationships, calm navigation, content-led variation.
- Product: task completion, predictable placement, complete states, repeated patterns, selected brand moments.
- Dashboard/tool: useful density, strong grouping, aligned numbers, stable controls, color for meaning.
- Commerce/premium: product evidence, trust, tactile detail, purchase clarity.
- Public/regulated: trust, accessibility, plain language, and error prevention.

## Redesign inspection

For `preserve-and-modernize` or `visual-overhaul`, expand inspection only where the change could disturb a shared contract: brand tokens and signature cues; information architecture, routes, navigation, and conversion; reusable patterns and exceptions; content that earns its space; responsive, accessibility, performance, and state behavior; analytics, SEO, and form contracts. Preserve route structure, content semantics, brand assets, tracking hooks, and legal copy unless explicitly in scope. Start with low-risk, high-leverage corrections before structural recomposition.

## Finding template

Write one block per issue:

```text
Priority: [P0/P1/P2 or project scale]
Location: [route, component, state, viewport, or source line]
Observed: [reproducible source or rendered fact]
Expected: [brief, identity, accessibility, or product principle]
Consequence: [user, business, maintenance, or trust impact]
Correction: [smallest practical next action]
Verification: [check that would prove the correction]
Limitations: [missing render, state, asset, or contract evidence]
```

Order findings by impact, then confidence. The audit is complete when every finding is observable, prioritized, actionable, and explicit about unverified evidence. If rendering is unavailable, perform source-level checks and say visual verification was not run.

# Visual system reference

Load for implementation or a detailed visual audit after project inspection. Treat the brief, audience, content, identity, constraints, and supported product behavior as the source of truth.

## Dials

For substantive work, choose values from 1–10 using the task:

| Surface | Variance | Motion | Density |
|---|---:|---:|---:|
| Public/regulated/accessibility-critical | 2–4 | 1–3 | 4–6 |
| Dense dashboard/operational tool | 3–5 | 2–4 | 7–9 |
| Mainstream product/SaaS app | 4–6 | 3–5 | 5–7 |
| Marketing/launch | 6–8 | 4–6 | 3–5 |
| Premium consumer/brand launch | 7–8 | 5–7 | 2–4 |
| Creative studio/campaign/portfolio | 8–10 | 7–9 | 2–4 |
| Editorial/long-form | 5–7 | 2–4 | 3–5 |

For preserve-and-modernize, estimate current values and adjust deliberately. `DESIGN_VARIANCE` changes alignment, scale contrast, overlap, and rhythm—not random decoration. `MOTION_INTENSITY` adds choreography only for hierarchy, feedback, causality, or narrative. `VISUAL_DENSITY` increases useful information and shortens travel while preserving grouping and scan order. Reduce spatial variance on small screens before sacrificing hierarchy or legibility. Values must be numeric and within 1–10; another designer should be able to predict the result.

## Build the system

### Typography

Give display, body, label, and data text distinct jobs. Build hierarchy with size, weight, width, spacing, and contrast rather than size alone. Choose type from identity and content; a serif is appropriate only when editorial, literary, heritage, or luxury evidence supports it. Keep emphasis within one family unless a deliberate mixed system is part of the brief or thesis. Keep body measures readable, line height comfortable, and large italics free of clipped glyphs. Use uppercase labels only when they orient; do not repeat an eyebrow above every section.

### Color and material

Use one palette with a clear neutral temperature and semantic roles. Choose the accent from brand or subject and apply it consistently to actions, links, focus, and highlights. Calibrate saturation to tone: premium is not automatically beige/brass and technology is not automatically purple-blue glow. Give gradients, transparency, blur, glow, grain, borders, and shadows a material or hierarchy role. Check actual text, controls, focus, and information states against their backgrounds. Keep radius, control, elevation, and page-theme language coherent.

### Composition and rhythm

Make the primary task and reading order obvious before novelty. Only for marketing or launch surfaces, compose the hero/opening viewport as one clear moment with a concise value proposition, short support, prioritized action, and real proof placed where it supports conversion. Other surfaces should compose their opening around their actual job: task, reading, monitoring, browsing, or purchase. Vary layout by section job; use meaningful scale, alignment, span, and whitespace within a stable grid. Use cards for grouping, interaction, or elevation; use spacing and dividers when a box adds no meaning. Give grids only the cells content needs. Keep desktop navigation compact and stable; prevent accidental wrapping.

### Imagery, icons, and motion

Use supplied assets and real product captures for product evidence, context, process, people, place, or atmosphere. A real interface needs real evidence or a working preview, not decorative screenshot rectangles. Text-led composition is valid when intentional; if essential imagery is unavailable, name the asset and placement. Give informative visuals meaningful alt text, decorative visuals empty alt, and captions only when useful. Use the project's icon family; an authorized addition must be coherent in optical style, stroke/fill, integration, and labeling. Custom marks require authorized identity work and visual verification. Give animation a reason, avoid layout churn, choreograph a few high-value moments, and make continuous motion pausable and reduced-motion safe. Preserve state and comprehension with motion disabled.

### Content and interaction

Use one voice, concrete claims, and functional labels. Never fabricate metrics, testimonials, customers, precision, scarcity, or faux metadata; mark sample data. Use one label for the same action and context. For changed interactions, implement only supported states; changed fields need persistent labels, contextual errors, and obvious recovery.
